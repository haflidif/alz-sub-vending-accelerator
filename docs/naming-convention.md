# Naming convention

## Subscription YAML files & alias

Each subscription is one flat file at `landingzones/<archetype>/<sub-name>.yaml`.

`<sub-name>` follows: `<env>-<archetype>-<workload>[-<seq>]` — all lowercase, hyphen-separated.

| Segment | Examples | Notes |
|---|---|---|
| `env` | `prod`, `nonprod`, `dev`, `test` | Lifecycle/environment label |
| `archetype` | `corp`, `online`, `sandbox` | Must match a key in `terraform/archetypes.tf` |
| `workload` | `erp`, `web`, `analytics`, `iot` | Short application/system identifier |
| `seq` | `001`, `002` | Optional; use when multiple subs share the first three segments |

Examples:
- `landingzones/corp/prod-corp-erp-001.yaml`
- `landingzones/online/prod-online-web-001.yaml`
- `landingzones/sandbox/dev-sandbox-platform-001.yaml`

The filename (minus `.yaml`) is the default `aliasName` and `displayName`
for the subscription — both can be overridden inside the YAML.

> ⚠️ `aliasName` is **effectively immutable** after subscription creation.
> Choose carefully; renaming requires recreation.

## Resource groups created by the AVM module

| RG | Naming |
|---|---|
| Network spoke | `rg-<aliasName>-network` |
| Network Watcher | `NetworkWatcherRG` (Azure-managed name; do not rename) |
| Identity (UMI) | `rg-<aliasName>-identity` (default; overridable) |

## VNet / peering

| Resource | Naming |
|---|---|
| Spoke VNet | `vnet-<aliasName>` |
| Hub-peering name | auto-generated by the AVM module |

## Tags applied automatically

Tag names match the platform landing zone
(e.g. `alz-core/platform-landing-zone.auto.tfvars` in your platform-LZ repo)
so resources merge cleanly across the platform / spoke boundary.

| Tag | Source | Default |
|---|---|---|
| `managedby` | `mandatory_tags` | `terraform` |
| `source` | `mandatory_tags` | `avm-ptn-alz-sub-vending` |
| `deployedby` | `mandatory_tags` | `subscription-vending-pipeline` |
| `archetype` | archetype config | `corp` / `online` / `sandbox` |
| `businessowner` | sub YAML `owner` | (required) |
| `technicalcontact` | sub YAML `technicalResponsible` | falls back to `owner` |
| `costcenter` | sub YAML `costCenter` | `unassigned` |
| `workloadname` | sub YAML `workloadName` | falls back to filename (`aliasName`) |
| `<cost_allocation_tag_key>` | sub YAML `costAllocationCode` | configurable — see [tagging.md](tagging.md) |
| `environment` | sub YAML `workload` (or archetype-forced) | `Production` (set `workload: DevTest` in sub.yaml to opt in — requires EA/MCA Dev/Test entitlement) |

Caller tags from the sub YAML `tags` map are merged FIRST so governed tags
always win on conflict. Reserved keys are rejected at plan time — see
[docs/tagging.md](tagging.md).
